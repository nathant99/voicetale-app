# Handoff from Hub — Voicetale Cast Portraits

Direction: **hub → app**. Cast portrait assets shipped to the app repo + distributed to spark-anvil-site `/cast/<app>/<char>` rendering surface.

## The decision

Per `spark-anvil-hub/Docs/AUDIT_NEXT_BATCH_HANDOFF_COMPLETENESS_2026-06-19.md` (Wave V methodology extension to top-8 docs-only apps), all 8 audited apps had cast portraits shipped to disk but no handoff doc explaining what they are + how to consume. This handoff closes the documentation gap.

**Pattern B note** (ELA / Voice-craft): Per `.claude/rules/distributed-narrative.md` § Hero mascot vs. cast Pattern B, this app's hero mascot stays the protagonist; the cast members are framed as the hero's friends. Cast portraits surface the friends individually; the hero mascot's portrait is rendered separately via the standard `IllustrationRegistry` mascot pose set.

## What shipped

| Asset class | App-repo path | Site path | Count |
|---|---|---|---|
| Cast portraits (neutral 3/4 head-and-shoulders) | `Resources/Cast/<char>.webp` (256×256 alpha) | `spark-anvil-site/public/cast/voicetale/<char>.webp` | 4 app / 4 site |

The site count may exceed the app count when the app's cast includes mentor / ensemble characters beyond `dnCast.members[]` (e.g., narrator anchors, captain figures, ensemble cohorts). Those exist as portraits for the `/cast/<app>` site index but not as bundled assets the app needs to render.

## How they're used

### Site-side (already wired)

- `/cast/<app>/<char>` page renders the portrait as the per-character chapter hero sidebar
- `/cast/<app>` aggregate page renders the portrait as the per-character card thumbnail
- Homepage Strip 4 "Freshly Updated Cast" surfaces the portrait + character name

### App-side (recommended integration)

```swift
import ForgeIllustrations

// In your CharacterDirectoryView or equivalent:
let registry = IllustrationRegistry.shared
if let illustration = registry.illustration(named: "<char>") {
    illustration.image
        .resizable()
        .aspectRatio(contentMode: .fit)
}
```

If your app uses `IllustrationRenderer` from `ForgeUI`, the portrait surface drops in directly. Cast portraits are NOT avatar accessories — do NOT register them via `AvatarAssetCatalog(appBundles:)`; that catalog is reserved for `ForgeAvatar.AvatarLayer` types per `.claude/rules/forgekit.md` § Avatar Edit Authority.

## Convention compliance

These portraits are generated by `spark-anvil-hub/scripts/gen_cast_portraits.py` which adopts the R-PATH-B-PROMPT-PARITY 3-block prompt pattern per `.claude/rules/spark-anvil-website.md` § "Portrait companion":

- CHARACTER IDENTITY block (LOAD-BEARING) — YAML front-matter + opening passage + species-defaulting clause
- POSE / FRAMING — neutral 3/4 head-and-shoulders; transparent background
- STYLE — `STYLE_REGISTRY[app_slug]` per-app palette override OR `_DEFAULT_STYLE` chunky-cartoon outline + cell-shading

Per R-CAST-PORTRAIT-SLUG (codified in `.claude/rules/spark-anvil-website.md`), the portrait filename slug at `public/cast/<app>/<char>.webp` MUST match the chapter MD filename slug at `<app>-app/Docs/dn-s/chapters/<char>.md`. The site's prebuild chain runs `spark-anvil-hub/scripts/audit_cast_portrait_coverage.py --json` and FAILS the build if any portrait is missing for a chapter.
