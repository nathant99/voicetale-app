PR #124 changed `Packages/Libraries/Package.swift` (bumping the ForgeKit pin) which forced `xcodebuild -resolvePackageDependencies` to regenerate `VoiceTale.xcworkspace/xcshareddata/swiftpm/Package.resolved`. Future rounds that bump a pin should commit `Package.resolved` in the same PR.

### ForgeAvatar API shape (post 1.0.0-rc.1)

The new ForgeAvatar API per labsmith ADR-022 is a portfolio-wide simplification. Future VoiceTale work touching `AvatarStudioSheet.swift` should reference the new shape: single-presentation `AvatarStudioView(initialConfig:baselineEditedAt:displayName:appGroupStore:onSaved:onCancelled:)` — no `catalog:` parameter, no `Presentation` enum. The `AvatarConfig` shape is now 2 fields (`tintIndex: Int` + `glyph: AvatarGlyph`) with `paletteHexes` exposing 12 Material You HCT tone-locked colors. Per-app theming via `AvatarThemedGlyphProvider` protocol + `ForgeAvatarRegistry.shared`. The CHANGELOG entry for 1.0.0-rc.1 is the canonical migration spec; `Packages/Libraries/Sources/AppFeature/ProfileTab/AvatarStudioSheet.swift` (post-PR #124) is the VoiceTale reference impl.

### ForgeKit pin pattern for prerelease versions

The `from: "1.0.0-rc.3"` pin form accepts 1.0.0-rc.3 → 2.0.0 (exclusive) per SPM semantics — including subsequent 1.0.0-rc.4, 1.0.0, 1.0.x, 1.y.z. When `1.0.0` final ships, no Package.swift change is required; Xcode's "Update to Latest Package Versions" picks it up. When the 1.0.0 → 2.0.0 transition happens, a manual bump becomes necessary.
